## 1. Executive Summary & Objective

The primary objective of Phase 7 is to empirically validate and evaluate three complete Maximum-Flow / Minimum-Cut algorithms implemented in `js/model/flow-solvers.js`:

1. **Edmonds–Karp (BFS-based Shortest Augmenting Path):**
   - **Theoretical Complexity:** $\mathcal{O}(|V| \cdot |E|^2)$.
   - **Classification:** **Strongly polynomial** — the bound depends solely on the number of vertices and edges and is entirely independent of edge capacity values or flow magnitude.

2. **Ford–Fulkerson (Deterministic Iterative DFS):**
   - **Theoretical Complexity:** $\mathcal{O}(|E| \cdot |f^*|)$ under standard integer-capacity assumptions, where $|f^*|$ is the numerical value of maximum flow.
   - **Classification:** **Pseudo-polynomial** — runtime depends directly on the numerical value of the maximum flow $|f^*|$, requiring exponential time relative to input bit length in worst-case pathological graphs.

3. **Widest-Path / Fat-Path (Max-Heap Priority Queue):**
   - **Theoretical Complexity:** $\mathcal{O}(|E|^2 \log |V| \log |f^*|)$ (or $\mathcal{O}(|E|^2 \log |V| \log(U \cdot |V|))$, where $U = \max c(e)$) under integer-capacity analysis.
   - **Mechanism:** Each path search uses a modified Dijkstra traversal with a binary max-heap taking $\mathcal{O}(|E| \log |V|)$ time. By pushing along maximum-bottleneck paths, the remaining unrouted flow decreases by at least a factor of $(1 - 1/|E|)$ per iteration, bounding the number of augmentations by $\mathcal{O}(|E| \ln |f^*|)$.
   - **Classification:** **Capacity-dependent / Weakly polynomial** — the bound depends logarithmically on the numerical value of capacities/flow ($\log |f^*|$).
   - **Important Theoretical Qualification:** Observing invariant augmentation counts on one fixed graph topology under capacity scaling is an empirical observation specific to that graph's structure; it does **not** prove that the algorithm is strongly polynomial.

## 2. Experimental Design & Threat Mitigation

### 2.1 Graph Families and Topology Specifications
- **Sparse Directed:** $|E| \approx 2 \cdot |V|$, generated via Hamiltonian path from source to sink plus random directed forward edges to model sparse hallway networks.
- **Dense Directed:** Generated by establishing a Hamiltonian path and then including every remaining ordered pair $(u, v)$ with $u \neq v$ with independent probability $p \approx 0.5$. In a simple directed graph without self-loops, the maximum possible directed edge count is $|V|(|V|-1)$. The realized directed edge density $\frac{|E|}{|V|(|V|-1)}$ is **50%–60%**:
  - Dense-10V: $|V|=10, |E|=54$ out of 90 possible ($60.0\%$ density).
  - Dense-15V: $|V|=15, |E|=115$ out of 210 possible ($54.8\%$ density).
  - Dense-25V: $|V|=25, |E|=321$ out of 600 possible ($53.5\%$ density).
- **Grid / Room-Corridor:** $R \times C$ lattice mimicking orthogonal hallway grids with primary downstream exit directions and probabilistic cross-aisles.
- **Layered DAG:** Multilevel building architecture simulating floor-to-floor vertical stairwell evacuations with strictly forward inter-layer edges.
- **Capacity-Range Sensitivity Study:** Fixed 25-node, 50-edge sparse topology where capacities are independently generated across four ranges ($[1, 10]$, $[1, 100]$, $[1, 1000]$, $[1, 10000]$) using identical PRNG variates, testing performance under increasing numerical dynamic range while holding topology invariant.

### 2.2 Controlled Experimental Parameters
- **Deterministic PRNG:** Synthetic graphs are generated using an implementation of `xorshift128` initialized with fixed seeds (`seed = 42`), ensuring 100% cross-platform reproducibility without external npm packages.
- **Input Isolation:** Each solver run receives an isolated deep clone created via `cloneNetworkDef()`. In-place residual graph updates cannot leak across repetitions or algorithms.
- **Order Rotation:** Solvers are cyclically rotated across configurations (`(si + configIndex) % 3`) to neutralize OS scheduling, CPU cache locality, and JIT compilation biases.
- **Warm-Up Runs:** 3 discarded warm-up executions precede measured repetitions to stabilize V8 TurboFan tier-up optimization.
- **Timing Isolation:** Network generation, cloning, CSV formatting, and SVG chart generation are strictly excluded from the algorithm timing window.
- **Verification Guard:** Every single execution is verified through `verifySolverResult()`. Any run failing any of the 9 correctness invariants is flagged and excluded from summary aggregates.

### 2.3 Standardized Metric Definitions

| Metric | Field in CSV | Definition & Counting Convention |
|---|---|---|
| **Max Flow** | `maxFlow` | Net flow pushed from source to sink; verified independently against min-cut capacity. |
| **Total Runtime (ms)** | `totalMs` | High-resolution duration from solver entry to result return (`performance.now()`). |
| **Initialization (ms)** | `initMs` | Time spent building the collision-free composite key residual network. |
| **Core Search (ms)** | `coreMs` | Time spent exclusively in the path-search and augmentation while-loop. |
| **Augmentations** | `augmentations` | Exact count of successful flow-pushing residual paths. |
| **Search Attempts** | `searchAttempts` | Total path explorations completed ($k$ successful augmentations $+ 1$ final unsuccessful search confirming optimality). |
| **Edge Examinations** | `edgeExaminations` | Cumulative residual slots inspected during traversals, including saturated edges rejected due to $\text{remCap} \le 10^{-9}$. |

## 4. Rigorous Scientific Analysis of Findings

### 4.1 Capacity-Range Sensitivity Study: Empirical Observations vs. Complexity Classes
In the capacity-range sensitivity study on the fixed 25-node sparse graph:
- **Edmonds–Karp:** Required 3 augmentations at $[1, 10]$ and stabilized at exactly 4 augmentations across $[1, 100]$, $[1, 1000]$, and $[1, 10000]$. This stability reflects BFS shortest-path routing, where augmentation sequences are governed by topological distance rather than capacity scale.
- **Ford–Fulkerson (DFS):** Augmentation count jumped from 5 to 12 when maximum flow scaled from 5 to 38. This empirical sensitivity illustrates how DFS is prone to taking small-volume path augmentations as the total flow volume increases, in line with its theoretical dependence on $|f^*|$.
- **Widest-Path:** Empirically required exactly 2 augmentations across all four capacity tiers on this particular network.
  > **Crucial Research Qualification:** This empirical invariance on a single fixed network **must not be claimed as proof that Widest-Path is strongly polynomial**. The theoretical bound for widest augmenting path under integer capacities is $\mathcal{O}(|E|^2 \log |V| \log |f^*|)$, which is weakly polynomial because it depends on $\log |f^*|$. In this specific 25-node synthetic topology, the first two fat paths happened to saturate the minimum cut completely, preventing any logarithmic tail of smaller residual augmentations.

### 4.2 Dense Graph Degradation of DFS Ford–Fulkerson
On the 25-node dense graph ($|E| = 321, 53.5\%$ directed density), DFS-based Ford–Fulkerson suffered severe performance degradation:
- It required **273 augmentations** and **81,711 edge examinations** ($3.13\text{ ms}$).
- In contrast, Edmonds–Karp required only **32 augmentations** ($1.11\text{ ms}$), and Widest-Path required only **17 augmentations** ($0.53\text{ ms}$).
- This demonstrates the vulnerability of unguided DFS in dense graphs: DFS readily explores long, winding paths with tiny bottleneck capacities, repeatedly modifying residual capacities without making significant progress toward the maximum flow.

### 4.3 Practical Recommendations for Campus Evacuation Planning
1. **Interactive Visualization Default:** **Edmonds–Karp** is the optimal default algorithm for building evacuation tools. Shortest-path routing is intuitive for human evacuation (fewest room-to-hallway transitions), and its $\mathcal{O}(|V| \cdot |E|^2)$ strongly polynomial bound guarantees predictable performance regardless of corridor occupancy numbers.
2. **High-Congestion Bottleneck Analysis:** **Widest-Path** provides superior insight when campus planners want to identify primary arterial evacuation corridors first, as it pushes maximum evacuation volume per iteration and minimizes the total number of route redistributions.
3. **Educational Value of Ford–Fulkerson:** DFS-based Ford–Fulkerson serves as a foundational pedagogical comparison, illustrating empirically why modern flow networks require guided path selection (BFS or fattest path).
